## Why

On a Good-3G-class link (1.6 Mbps, 150 ms RTT, 390×844 @2x) the site reaches DCL in 4501 ms and renders **10 of 17 images as sourceless holes** — while googlebook.google, transferring 4.29 MB against our 2.66 MB, reaches DCL in 1497 ms with **zero** empty images. The gap is not payload size. It is that Google spends its bytes on device-matched assets that are always attached to something visible, and we spend ours on 2048 px photos, 293 KB of webfonts, and a lite tier whose specified behavior is to _remove_ image sources. `adaptive-media-tiering` is working exactly as written; what it was written to do produces the symptom.

A second, separate gap: `#loading-screen` is an opaque `fixed inset-0 z-50` layer dismissed only by JavaScript, and unlike `WelcomeGate`, `ZoomParallax` and `VenueMap` it has no `<noscript>` escape — so a guest with scripting blocked is left behind it permanently.

One earlier reading is corrected here rather than repeated below. The 9 of 9 `[data-scroll-fade]` elements measured at opacity ~0 were off-screen participants in their _intended_ pre-reveal state, measured with JavaScript enabled; nothing in `src/` sets that attribute below 1 in delivered CSS, so the reveals already satisfy the visibility floor. They are not part of the defect, and this change only locks the invariant in with a test. See `design.md` D5.

## What Changes

- **Every raster image ships device-matched candidates.** Add `srcset`/`sizes` and intrinsic `width`/`height` to the collage (`ZoomParallax`, 10 images), the timeline photos (`TimelineScroll:90/117/150` — this is where `keluarga-acik` and `keluarga-yofri` actually live), the event cards (`EventTimes:58`) and the gate background (`WelcomeGate:45`). Today 1 of 19 `<img>` has a `srcset`, and a 390 px phone downloads `keluarga-acik` at `width="2048"`, 463 KB. Generate ~390/768/1280 px AVIF+WebP variants at build time. `HeroZoom:9` is already complete.
- **No image element is ever sourceless.** Replace the deferred-to-`data-src` pattern with a _candidate downgrade_: a low-resolution placeholder is always present in `src`, and promotion swaps in higher-resolution candidates rather than adding a source from nothing. `wedding_photo_blur.webp` (18 KB) already establishes the pattern; extend it.
- **BREAKING (spec-level): the `lite` tier no longer strips sources.** `media-tiering`'s "ships without an active `src`/`srcset`" requirement is amended so deferral changes _which candidate_ loads, never _whether one_ loads. The static-grid collapse, the absent parallax binding, the tap-only video, and the silent soundtrack all stand unchanged.
- **Font diet.** Switch Fraunces from the all-axes `full.css`/`full-italic.css` entrypoints to `standard.css`/`standard-italic.css` (weight + optical-size axes, dropping SOFT and WONK), drop the redundant `@fontsource/geist-sans` static family (the `--font-sans` token resolves `Geist Variable` first, and the measured load fetched none of its files), and `preload` the single latin variable `woff2`. Fraunces italic stays — `HeroZoom.astro:58` and `RsvpSection.astro:252` both render it. Target: **293 KB actually transferred → ≤ 200 KB**; the build references 936 KB across 19 files today, most of it subsets no page renders.
- **Resource hints.** Add `preconnect` for the basemap tile origins, `preload` for the critical latin serif `woff2` (resolved through a Vite import, since the built file is content-hashed) and for the hero candidate via `imagesrcset`/`imagesizes` — a bare `href` cannot express a `srcset` selection and would double-fetch a discarded format. `fetchpriority="high"` is **already** on the hero (`HeroZoom.astro:17`) — and also on `WelcomeGate.astro:49`, which must lose it so the single-priority requirement holds once the couple supplies that asset. Add `loading="lazy"` below the fold except the collage. Today the build emits zero `preload` and zero `preconnect` hints.
- **Overlays must not trap a no-script guest.** Add the `<noscript>` + `@media (scripting: none)` escape for `#loading-screen`, using the idiom `WelcomeGate` already establishes. Separately, **codify** the reveal visibility floor that already holds — a comment recording the invariant, plus a no-script regression case that task 3.6 **defers to the testing pass and does not write here** — without changing `scroll-fade.ts` behavior. Reduced-motion behavior is unchanged.
- **Non-goals:** no change to the tier _probe_ (verdict logic, 220 KB/s floor, one-way ratchet), no change to `public/` cache headers — that `no-cache` + ETag policy is load-bearing for the probe's warm-cache locality inference, and revisiting it needs its own change. Video strategy and the soundtrack are untouched. Generated variants of private media MUST NOT be committed: `apps/web/public/` holds real photos locally under `skip-worktree` with placeholders in the repo, so variant output goes to a gitignored path.

## Capabilities

### New Capabilities

- `responsive-media`: device-matched raster delivery — `srcset`/`sizes` candidate sets, intrinsic dimensions on every image, build-time variant generation, LCP priority signalling, and the rule that an image element always carries at least one fetchable source.
- `webfont-delivery`: the font payload contract — one family per typographic role, subset and axis budget, `font-display` behavior, preloading of the critical file, and no legacy formats for engines that support `woff2`.
- `progressive-enhancement`: the visibility floor — delivered markup renders complete content without JavaScript, no script-dismissed overlay traps a no-script guest, scroll-driven reveals never hide content that has not been animated, and any deferred upgrade has a visible predecessor state within a hard per-placeholder byte cap.

### Modified Capabilities

- `media-tiering`: "Tier-driven promotion of deferred collage media" changes from source _removal_ to candidate _downgrade_ — a lite or pending tier ships a placeholder source and promotes resolution, so no tier produces an image hole. The lite collapse, binding teardown, video, and soundtrack requirements are unaffected.
