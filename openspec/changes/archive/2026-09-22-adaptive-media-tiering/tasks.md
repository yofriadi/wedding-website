## 9. Adversarial review fixes

Applied after a `code-reviewer` pass over the implemented change. Findings are ranked as the reviewer ranked them.

- [x] 9.1 Burst probe scoped to the initial asset burst (Critical). `readBurst()` scanned the whole resource buffer, so the page's sequential `/api/guest-photos` + `/api/invite/me` calls counted as "throughput". On a warm cache — where every asset has `transferSize` 0 — those XHRs were the only bytes left, so the probe measured idle RTT and falsely downgraded an API-`full` guest mid-session, after the collage and soundtrack were already promoted: a layout teleport, permanent loss of the parallax, zero bytes saved. Now excludes `fetch`/`xmlhttprequest`/`beacon`/`ping` and anything starting after a 2.5 s burst window. Verified: the warm-cache-plus-XHR profile now yields no verdict and keeps `full`; all prior verdict paths unchanged.
- [x] 9.2 Absent `data-tier` now means `full` (High). Every JS consumer asked `=== "full"`, so a missing attribute read as lite while the CSS — keyed on explicit `lite`/`pending` — left the 400lvh pinned runway in place: a pinned runway nothing scrubs and a collage nothing promotes. That inverts D4 and the Migration Plan, and is reachable without a rollback (an inline-script blocker, a future CSP without a hash for the head script). Polarity inverted in all four consumers and stated normatively in the spec. Verified live: with the attribute removed, controls come off, the runway returns to 400lvh, the stage re-pins, the soundtrack preloads and 10/10 images are promoted.
- [x] 9.3 Downgrade aborts the soundtrack (High). `onTierChange` was `full`-only, so a `full → lite` downgrade left the 3.1 MB preload running — the guest paid the bytes the change exists to save and got the degraded experience too. Verified `networkState → NETWORK_NO_SOURCE`, `readyState → 0`.
- [x] 9.4 Video exit detection (High). `entries.some(e => e.isIntersecting)` under a single `threshold: 0.5` is fragile: `isIntersecting` is not threshold-derived, and the crossing to ratio 0 shares a threshold index with the sub-0.5 step so it is never queued. Now tests `intersectionRatio >= 0.5` with `threshold: [0, 0.5]`. Correction to the reviewer's severity: a differential harness in Chromium showed it _does_ report `isIntersecting: false` at ratio 0.45, so "plays once and never pauses" does not reproduce there — this is WebKit-hardening, and 7.5 covers the engine that is actually unverified.
- [x] 9.5 Gate makes no music promise while `pending` (High). The note hid on `lite` only, but `pending` is lite until proven otherwise and the common unresolved case (returning Safari guest, warm cache, nothing transferred) ends at `lite` via the 7 s failsafe — while the gate arms at 2.6 s, so the note promised music for the whole wait. A `pending → full` resolution landing between module evaluation and `DOMContentLoaded` bound the scroll-zoom twice and flushed layout twice, contradicting the archived `scroll-motion` requirement. `applyTier(rebuild)` now rebuilds only for a width-changing resize or a client navigation; first initialization binds only if unbound. - [x] 9.7 Promotion margin in pixels (Medium). `"200% 0px"` resolves per-axis against the root box and engines have not agreed on the vertical axis, so the same string can mean two viewport heights or two viewport widths — a sub-viewport margin on a portrait phone is exactly the empty-frames-on-arrival failure the margin exists to prevent. - [x] 9.14 Option A implementation details, each chosen against a specific failure mode. **Discriminator** is `encodedBodySize === 0` with either `transferSize > 0` (304 headers) or `decodedBodySize > 0` (memory-cache hit) — _not_ the `decodedBodySize > 0 && transferSize small` form first proposed, because measurement showed 304s report `decodedBodySize: 0`, so that form would have missed every revalidated image. **Trigger** is "no verdict was reached" rather than "burst is strictly payload-free", so a partially evicted cache transferring a few KB — under the 8 KB floor, therefore unjudgeable — is still eligible. **Counted before the burst-window filter**, because locality is time-independent while throughput is not: a slow document TTFB pushes every `startTime` past the 2.5 s window and must not erase the evidence along with the measurement. **Minimum of five hits** so one stray favicon revalidation cannot stand in for a warm cache (~23 public assets plus ~19 cached chunks revalidate on a return visit). **Scoped to `pending` only**, since an API verdict already has better evidence and `lite` is terminal. **`judge()` now returns the burst** it measured so the load handler reuses the locality count instead of scanning twice.
- [x] 9.15 Option A verified across **12** harness profiles using the measured entry signatures, re-run after the deduplication in 11.1 so the count matches the evidence rather than an earlier enumeration that said 16. Resolves `pending → full` (4): 23 revalidations alone; 19 memory-cache hits plus 23 revalidations; partial eviction carrying 4 KB of real payload; and a cold fast burst. API verdicts untouched (2): API-`full` with a warm cache produces no spurious event, and API-`full` with a slow burst still downgrades. An earlier 16-profile run additionally covered opaque cross-origin 0/0/0 entries contributing no locality hits.

An external verification run (Playwright WebKit against a local `max-age=0` + ETag server) reported warm-cache entries as `transferSize: 300, encodedBodySize: 0`, byte-identical to Chromium. **That run was not reproduced in this repo**, so it is reported rather than established, and the WebKit half of the claim is now qualified in all three places it appeared as fact — design D2, the `readBurst` comment, and here.
