## 2. RSVP API (apps/web/src/pages/api/rsvp/)

- [x] 2.1 Create `apps/web/src/lib/invite-session.ts`: shared `INVITE_COOKIE_NAME`, `INVITE_ID_RE`, uniform `notFound()`, `serviceUnavailable()` (extracted from `api/invite/me.ts` — third consumer stops copy-paste; migrating the two existing copies is optional).
- [x] 2.2 Create `apps/web/src/lib/rsvp.ts`: single `getConfirmedGuestCount()` = `COALESCE(SUM(party_size), 0)` over `attending = true` (SQLite `SUM` over zero rows returns `NULL` — coerce). Used by both `count.ts` and the section frontmatter so the aggregate logic exists exactly once.
- [x] 2.3 `GET /api/rsvp` (`apps/web/src/pages/api/rsvp/index.ts`): resolve invite via shared helper → `200 { attending, partySize, maxPartySize }` (`null,null` when no row); uniform 404 for missing/malformed/unknown cookie; 503 on DB error; `no-store` on every response. Read-only — no metrics touch.
- [x] 2.4 `POST /api/rsvp`: **authenticate first** — resolve cookie (uniform 404) BEFORE reading/parsing the body, so anonymous callers get 404 even with a garbage body (endpoint-invisibility rule). Then zod-validate `{ attending: boolean, partySize?: number }` → 400 `{ "error": "invalid_body" }`; attending requires `1 ≤ partySize ≤ max_party_size` → 400 `{ "error": "party_size_out_of_range" }`; declined stores `party_size = 0`. Upsert single row keyed by `invite_id` (drizzle `onConflictDoUpdate` set: `attending`, `party_size`, `updated_at` — **deliberately NOT `responded_at`**, first-response timestamp survives). `SQLITE_BUSY`/write failures → 503. `200` echoes stored `{ attending, partySize }`. No CORS headers (same-origin; `SameSite=Lax` cookie is the CSRF posture).
- [x] 2.5 `GET /api/rsvp/count` (`apps/web/src/pages/api/rsvp/count.ts`): `200 { count }` via `getConfirmedGuestCount()`; no cookie required; `no-store`; 503 on DB error.
- [x] 2.6 Scripted curl verification against a controlled build: anonymous/malformed/unknown 404 shapes identical to `/api/invite/me`; **anonymous + invalid body → 404 (not 400)**; submit attending + decline + change-of-mind round trips (verify `responded_at` unchanged across the change of mind); over-cap 400 with `party_size_out_of_range`; malformed body 400 with `invalid_body`; count sums correctly including declines and the zero-rows case; `no-store` on all responses; invite metrics columns unchanged after all calls; admin create-with-cap + list-with-RSVP round trip.
